# 논어 사료글 재구성 규칙

> 상태: 초안 v0.1  
> 확정 방법: 소장님이 제시하는 예시와 교정본을 반영한 뒤 v1.0으로 확정한다.

## 1. 작업의 성격

이 작업은 오탈자나 어색한 문장만 고치는 교정이 아니다. 각 장에 딸린 원문·사료·현재 글을 재료로 삼아, 모바일 카드에 들어갈 한 편의 짧은 교양 글로 **전체를 다시 구성하는 작업**이다.

현재 문장에 문제가 없더라도 더 좋은 흐름을 만들 수 있다면 고친다. 문장 순서, 문단 구성, 시작과 끝, 인용문의 위치를 모두 바꿀 수 있다. 원문의 문장 수와 문장 구조를 보존할 필요도 없다.

판단 기준은 “원문을 얼마나 그대로 남겼는가”가 아니라 다음 세 가지다.

1. 사료의 사실과 장의 핵심 뜻이 보존됐는가.
2. 처음부터 끝까지 한 사람이 쓴 글처럼 자연스럽게 이어지는가.
3. 제한된 분량 안에서 읽을 가치와 여운이 있는가.

## 2. 반드시 보존할 것

- 인물, 사건, 시대, 장소, 연도, 발언자와 해석자의 구분
- 경문의 핵심 뜻과 문답 관계
- 사료가 명시한 사실관계
- 직접 인용문의 취지
- 학자별 해석 차이가 중요할 때 그 차이
- JSON의 장 ID와 원문 등 작업 대상이 아닌 필드

사실을 매끄럽게 만들기 위해 인과관계를 지어내지 않는다. 뒤의 사건이 앞의 말씀을 입증한 것처럼 단정하지 않는다. 확실하지 않은 전승은 사실처럼 못 박지 않는다.

## 3. 자유롭게 바꿀 수 있는 것

- 문제가 없는 문장까지 포함한 전면 재작성
- 문장의 순서, 길이, 주어와 서술어
- 여러 문장의 통합 또는 한 문장의 분리
- 설명과 인용의 배치
- 반복되거나 가치가 낮은 정보의 생략
- 이해에 필요한 짧은 연결 설명의 추가
- 시작 문장과 마지막 문장의 교체
- 같은 사실을 더 정확하고 자연스러운 한국어로 다시 표현하는 일

단, 추가 사실은 출처로 확인할 수 있거나 널리 확립된 사실일 때만 쓴다. 기억에 의존한 세부 사항이나 극적인 장면은 보태지 않는다.

## 4. 구성 원칙

먼저 이 장에서 독자에게 남길 중심축 하나를 정한다. 인물의 성격, 문답이 나온 사정, 경문의 핵심 쟁점, 후대 해석 가운데 가장 적합한 것을 중심축으로 삼는다.

글은 대체로 다음 요소를 필요에 따라 조합한다.

- 독자가 바로 들어갈 수 있는 인물·상황
- 경문의 질문이나 핵심 발언
- 그 말이 겨냥한 문제
- 주희 등 후대 해석자의 풀이
- 생애나 후일담이 실제로 글을 닫아 줄 때의 결말

이 순서를 매번 틀처럼 반복하지 않는다. 모든 장에 억지로 일화·주희·교훈·여운을 하나씩 붙이지 않는다. 각 문장은 앞 문장에서 자연스럽게 생겨나야 한다. 마지막 역사 사실을 단순한 연표처럼 덧붙이지 않는다.

## 5. 문체

목표 문체는 **쉽게 읽히는 역사 교양문에 아주 약한 문학성을 더한 한국어**다.

- 논어를 처음 읽는 사람도 한 번에 이해할 수 있게 쓴다.
- 공자님은 존칭한다.
- 설명은 정확하되 논문·주석 문체로 굳히지 않는다.
- 독자에게 과하게 말을 걸거나 감탄을 유도하지 않는다.
- 번역문의 어순을 버리고 자연스러운 한국어 어순으로 다시 쓴다.
- 추상명사를 연달아 쓰지 말고 가능한 한 사람과 행동이 보이게 쓴다.
- 같은 낱말과 같은 어미가 가까이 반복되지 않게 한다.
- “그것”, “이를”, “여기”처럼 가리키는 대상이 흐린 표현은 줄인다.
- 꾸민 말보다 구체적인 사실과 문장의 연결로 힘을 만든다.

## 6. 피할 말투

다음 표현은 내용상 꼭 필요한 경우가 아니면 쓰지 않는다.

- “공자님의 대답은 단호했습니다.”
- “더욱 묵직하게 들립니다.”
- “잘 보여 줍니다.”
- “시사합니다.”
- “의미한다고 할 수 있습니다.”
- “단순히 A가 아니라 B입니다.”
- “그런 의미에서”
- “살펴볼 수 있습니다.”
- “주희는 여기 …”
- 사료를 하나씩 옮겨 붙인 듯한 “뒤에 …하였으나”, “성정은 그대로였습니다”
- 앞 문장을 추상어로 한 번 더 되풀이하는 해설

금지어를 기계적으로 다른 상투어로 바꾸지 않는다. 문장 전체가 필요 없다면 없앤다.

## 7. 분량

- 기본 목표: 공백 포함 300~350자
- 일반 허용 범위: 공백 포함 280~380자
- 원문의 중요한 사실을 지키기 위해 필요한 경우에는 범위를 조금 벗어날 수 있다.
- 분량을 맞추려고 연결 문장을 먼저 없애지 않는다.
- 수식어, 중복 설명, 원문을 되풀이한 문장부터 줄인다.
- 짧더라도 인물 → 발언 → 해석 또는 결말의 연결이 끊기면 다시 쓴다.

## 8. 장별 작업 순서

1. 장 ID·원문·사료·현재 글을 읽는다.
2. 바꾸면 안 되는 사실을 목록으로 뽑는다.
3. 글의 중심축과 끝맺음을 먼저 정한다.
4. 현재 문장을 보지 않고도 쓸 수 있을 만큼 구조를 새로 잡는다.
5. 전체를 한 번에 다시 쓴다.
6. 현재 글과 대조해 사실 누락·왜곡·불필요한 증가를 확인한다.
7. 글자 수와 문체를 검사한다.
8. JSON의 지정 필드에 수정본을 넣는다.

‘어색한 문장 찾기 → 그 문장만 바꾸기’ 방식으로 작업하지 않는다.

## 9. GitHub와 JSON 처리 규칙

- 받은 JSON을 원본으로 삼고 먼저 전체 장 수와 장 ID를 센다.
- 498장인지 499장인지 추측하지 않고 실제 파일로 확정한다.
- 작업 전 원본의 커밋과 파일 SHA를 기록한다.
- 장 ID, 원문, 사료, 출처 필드는 임의로 바꾸지 않는다.
- 수정 대상 필드만 고치며 JSON 스키마를 유지한다.
- 편별 또는 일정 묶음으로 수정하고 커밋한다.
- 같은 파일을 다른 작업이 동시에 고쳤는지 매번 확인한다.
- 덮어쓰기 전에 최신 파일 SHA를 다시 확인한다.
- 원문 장 수, 수정 장 수, 누락 ID, 중복 ID, 빈 수정문을 기계로 검사한다.

## 10. 예시를 통한 룰 확정

1. 소장님이 대표적인 예시 몇 장을 준다.
2. 이 규칙으로 수정 초안을 만든다.
3. 소장님이 직접 고치거나 문제점을 지적한다.
4. 초안과 소장님 교정본의 차이를 분석해 취향이 아니라 재사용 가능한 규칙으로 적는다.
5. 예시를 다시 써 보아 같은 문제가 재발하지 않는지 확인한다.
6. 소장님이 “됐다”고 확정하면 이 문서를 v1.0으로 올린다.
7. 확정 뒤에도 실제 작업에서 새 문제가 반복되면 사례와 처방을 규칙에 추가한다.

예시는 결과물만 보관하지 않고, **왜 소장님 수정본이 더 나은지**를 규칙으로 남긴다.

## 11. 출고 전 장별 검사

- 사실을 새로 지어낸 곳이 없는가
- 인물과 발언자의 관계가 뒤바뀌지 않았는가
- 주희의 해석을 경문 자체의 뜻으로 섞지 않았는가
- 역사적 후일담을 억지 인과로 만들지 않았는가
- 처음과 끝이 같은 중심축에 놓였는가
- 문장 사이에 뜬금없는 점프가 없는가
- 직역투·AI 상투어·추상적인 총평이 남아 있지 않은가
- 글자 수를 줄이느라 필수 연결이 끊기지 않았는가
- 모바일에서 한 번에 읽히는가

## 12. 전체 작업의 완료 조건

- 입력된 모든 장 ID에 수정본이 있다.
- 누락·중복·빈 글이 없다.
- 각 편의 장 수가 입력 원본과 같다.
- JSON 파싱 오류가 없다.
- 샘플뿐 아니라 후반부까지 같은 문체 기준을 지킨다.
- 원문·사료·출처와 수정문 사이에 사실 충돌이 없다.
- 소장님이 확정한 예시의 특징이 전체 결과에 유지된다.
