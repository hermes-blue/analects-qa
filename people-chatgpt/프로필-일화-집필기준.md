# ChatGPT 인물 프로필·일화 집필 기준
버전: 1.4 / 시작: 2026-09-06 / 전체 평가 반영·2차 수정 파일럿: 2026-09-07

## 범위와 순서
원본 people 파일 순서로 한 명씩 진행한다. 한 사람의 메인 소개와 일화 최대 3개를 함께 완성하고 자체 평가한다. 사용자가 2026-09-06 걸닉부터 마지막 인물까지 추가 허락 없이 계속 진행하도록 승인했다. 한 명의 조사·집필·검수·업로드가 끝나면 곧바로 다음 인물로 넘어간다. 진행 중에는 짧게 상태를 알리고, 원고와 자체 평가는 인물별 JSON에 남긴다. 표제·사료조각·논어 속 장면은 이번 작업에서 제외한다.

## 자료와 집필
1. 기존 JSON에서는 이름·한자이름·순서·글자 수만 확인한다. 기존 문장과 소재를 초안의 토대로 읽지 않는다.
2. 인물을 독립적으로 검색하고 출전 원문을 확인한다. 정사·경전·역사 기록을 우선하되, 출전을 확인한 야사·설화도 허용한다.
3. 독립 검색으로 자료를 끝내 확보하지 못할 때만 기존 JSON을 재료 찾기의 단서로 삼는다. 이 경우 어떤 검색을 했고 무엇을 참고했는지 기록하며, 기존 문장을 옮기거나 바꾸어 쓰지 않는다.
4. 출전이 있다는 것과 실제 사건으로 확증되었다는 것을 구분한다. 후대 전승은 출전 표시에 성격을 기록하고, 독자가 사실로 오인하기 쉬운 내용에는 본문에서도 짧게 밝힌다.
5. 없는 사건·대사·심리·표정·행동을 만들지 않는다. 기록된 발언을 자연스럽게 번역하거나 간접화법으로 풀 수 있다.
6. 자료가 충분하면 서로 다른 사건 3개, 부족하면 1~2개만 쓴다. 한 사건을 쪼개거나 설명을 늘려 개수를 채우지 않는다. 확인된 일화가 없으면 0개와 사유를 남긴다.

## 말투와 분량
메인은 인물이 앱 독자에게 자신을 소개하는 일인칭이다. 제자는 공자를 스승님, 교유 인물은 공자님 등 실제 관계에 맞게 부른다. 일화는 삼인칭 존댓말로 쓴다. 인용문 외에서 시점을 섞지 않는다.
했습니다를 기본으로 하고 했지요 등은 리듬상 필요할 때만 섞는다. 인물마다 말투를 과장하거나 사극투를 쓰지 않는다.
각 인물의 기존 메인과 일화 글자 수를 먼저 확인해 그 안팎으로 맞춘다. 공백·문장부호를 포함한 Unicode 코드포인트로 세며, 제목은 본문 분량에서 제외한다. 이번 거백옥의 기준은 메인 151자, 일화 168~194자였다. 다른 인물에 일률적으로 200자를 강제하지 않는다.
메인에서 일화의 전 과정을 요약하지 않는다. 일화는 사건·대화·행동으로 전개하며, 마지막에 교훈이나 추상적 평가를 덧붙이지 않는다.

## 한 명씩 자가 개선
독립 조사 → 메인·일화 소재 배분 → 집필 → 자체 평가 → 효과가 분명한 부분만 1회 수정 → JSON 업로드·읽기 검증.
평가 항목은 가독성과 자연스러움, 사건의 흥미, 내용·전개 반복, 시점·호칭, 출전과의 일치, 분량이다. 점수를 장식적으로 매기지 말고 실제 문제와 조치를 짧게 남긴다.
다음 인물에서는 직전 개선점을 먼저 적용한 뒤 효과와 부작용을 다시 본다. 좋은 문장을 평가 기록을 만들기 위해 고치지 않는다.

## 001 거백옥 검수로 추가한 기준
- 그러고는 한마디를 덧붙였습니다 같은 안내는 삭제해도 흐름이 통하면 덜어낸다.
- 쓰이게 하지 못했다 같은 어색한 표현은 누가 무엇을 했는지가 보이는 말로 고친다.
- 세 일화의 도입과 끝맺음을 모두 인용 또는 해설로 통일하지 않는다.
- 다른 인물이 주로 행동하는 일화는 주인공의 처지가 실제로 달라지는 사건인지 확인한다. 거백옥의 등용 일화는 이를 충족하지만, 다음 인물에서는 본인의 행동이 드러나는 사건을 우선한다.

## 저장과 매핑
people-chatgpt/profiles/NNN-이름.json에 완성본과 출전·평가를 함께 저장한다. 인물 배열의 이름과 한자이름으로 매칭하고 인사와 층만 반영한다. 층은 새로 구성한 일화 배열 전체를 교체하며, 원본의 4개 항목과 새 3개 항목을 번호로 대응시키지 않는다. 앱 반영은 별도 작업이다.

## 자동 연속 진행 시 추가 점검
거백옥 3편 모두에 반복된 것이지요·것이었지요 같은 설명 연결을 기계적으로 이어 쓰지 않는다. 새 인물에서 실제로 적용한 개선점과 새로 발견한 문제만 기록한다.

## 001~080 전체 평가로 보완한 공통 편집 기준
1. 메인은 인물이 독자에게 하는 소개다. 한국어 이름 표기, 후대 기록의 유무, 조사·집필 과정의 설명은 출전·한계 필드로 옮긴다. 옮긴 분량을 채우려고 행동이나 심리를 만들지 않는다.
2. 집필 전에 메인과 일화의 소재를 배분한다. 메인은 신원·관계·처지·출전으로 확인되는 관심사를, 일화는 사건의 과정과 대화·결말을 맡는다. 자료가 적어 기본 사실이 겹치는 것은 허용하되 같은 줄거리를 두 번 요약하지 않는다.
3. 일화 마지막 문장을 가리고 읽는다. 없어도 사건이 이해되는 교훈·재요약·가상의 오해에 대한 해명은 덜어낸다. 전승임을 알리는 표지와 뜻을 바꾸는 필수 설명은 유지한다.
4. 제자의 메인은 스승님, 일화 서술은 공자님 등 합의한 존칭과 높임 서술어를 함께 확인한다. 공자가어 같은 책 제목이나 공자 규 같은 별도 고유 명칭은 자동 치환하지 않는다.
5. 자료가 적은 악사와 여덟 선비에게 명단·이동 기록·공유 전승을 새 개인 사건처럼 포장하지 않는다. 기록이 없다는 말을 반복해 길이를 늘리지 않는다. 확인한 직책과 생활 맥락이 독자의 이해에 필요한 경우에만 보탠다.
6. 글자 수는 각 인물의 원본을 기준으로 가깝게 맞춘다. 메인에서 20% 이상 차이가 나면 재검토 신호로 삼되, 이를 새 목표 분량이나 일괄 증량 허용치로 쓰지 않는다. 일화도 원본의 짧은 편과 긴 편의 폭을 살핀다.
7. 저는으로 시작하는 것 자체를 잘못으로 보지는 않는다. 도입 문구를 억지로 바꾸기보다 메인 전개와 일화의 사건 선택을 다양하게 한다. 했지요를 넣는 것만으로 자연스러워졌다고 평가하지 않는다.
8. 출전은 메인과 각 일화의 반영 위치를 알아볼 수 있게 연결한다. 장 번호가 다른 판본은 편명과 원문 첫 구절로도 식별한다.

## 누적 개선 적용 확인
기존의 직전 개선점과 함께 다음을 매 인물 확인한다: 일인칭 소개의 유지, 메인과 일화의 중복, 끝의 불필요한 해설, 호칭과 높임, 분량 채우기, 출전과 해석의 구별.
검수 결과에는 실제 고친 대목과 이유를 남긴다. 사실관계 주의사항을 적었다는 이유만으로 문체까지 개선되었다고 판정하지 않는다.
전체 평가 원문: profiles/ChatGPT-001-080-종합평가.json. 앞선 80명은 이 평가로 일괄 수정된 것이 아니며, 다음 집필부터 우선 적용한다.

## 전체 집필 후 2차 부분 수정
153명 1차 집필을 마친 뒤 사용자가 전체 평가 방향을 수용하고 001 거백옥부터 수정을 지시했다. 첫 인물의 수정 결과를 평가하여 다음 인물에 적용한다. 이 단계는 이미 독립 집필한 ChatGPT 원고를 편집하는 작업이다. 기존 people 원고를 새 문장의 재료로 삼지 않는 원칙은 유지한다.

1. 오탈자·호칭·이름 연결·원문보다 구체화된 장면을 먼저 확인한다. 이어 메인과 일화의 역할, 문장의 자연스러움, 분량을 검토한다.
2. 메인·일화·제목마다 유지할 근거를 먼저 판단한다. 실제 문제가 있는 부분만 수정하며, 모든 칸이나 문장을 바꾸는 것을 목표로 삼지 않는다.
3. 해설처럼 보인다는 이유만으로 문장을 삭제하지 않는다. 원인, 예법, 글자 모양, 전승의 성격 등 이해에 필요한 설명은 남긴다. 인물이 앱이나 조사 결과를 안내하는 말, 이미 끝난 사건의 반복 요약은 덜어낸다.
4. 원문에 있는 발언이 편집자의 의도 설명으로 바뀌어 있다면 실제 질문이나 답변을 자연스러운 간접화법으로 되살릴 수 있다. 발언을 새로 만들지는 않는다.
5. 긴 관형절은 원인과 결과 또는 행동의 순서가 바로 보이도록 손본다. 저는·했지요·것이지요를 일괄 금지하거나 대체하지 않는다.
6. 한 사건만 전하는 인물은 기본 사실의 겹침을 허용한다. 메인에서 일화의 결말까지 반복하는지 살피되, 둘을 달리 쓰기 위해 성격·동기·사건을 만들지 않는다.
7. 분량은 수정 전 ChatGPT 본문과 최초 원본의 글자 수를 함께 본다. 줄어든 부분에는 독해에 필요한 확인된 정보만 보태며, 자료가 부족하면 짧게 남긴다.
8. 개별 JSON의 수정이력에 변경 전후 문장, 유지 이유, 실제 글자 수, 수정 후 평가와 다음 적용 사항을 남긴다. 기존 1차 평가를 덮어쓰지 않는다.
9. 개별 JSON과 전체 통합 JSON을 함께 갱신하고 GitHub 재조회로 확인한다. 다른 인물의 본문이 바뀌지 않았는지도 확인한다. 작업현황에서는 1차 집필 완료 수와 2차 수정 완료 수를 구분한다.
